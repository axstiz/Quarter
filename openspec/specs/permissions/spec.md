# permissions Specification

## Purpose
Права доступа как отдельная настраиваемая система (spec-only). Роли (admin/editor/reader — по workspace-ам, см. capability auth) привязываются к действиям по матрице; матрица задаётся по умолчанию и MAY настраиваться админом workspace-а. Выдача прав — только админ workspace-а; выдача ролей и отдельных прав логируется.

## Requirements

### Requirement: Матрица прав по умолчанию

Сервис SHALL определять предустановленную матрицу прав: admin — все действия (в т.ч. управление участниками/правами, настройки workspace); editor — импорт/CRUD данных, приоритеты, отмена, факты спринтов, пересчёт, создание планов; reader — только чтение (все GET-ручки).

#### Scenario: Editor загружает факт

- **GIVEN** участник с ролью editor в workspace-е
- **WHEN** он загружает факт спринта
- **THEN** действие разрешено (право «спринт-факты» входит в роль editor)

### Requirement: Настройка прав админом

Админ workspace-а SHALL иметь возможность настраивать права своей компании: назначать/снимать роли участникам и включать/отключать отдельные права для ролей (например дать editor право подтверждать отмену). Сервис MAY ограничивать изменяемость части прав ради согласованности (admin-права неотчуждаемы: нельзя передать admin-доступ с себя, нельзя удалить владельца-workspace из списка admin-ов).

#### Scenario: Отключенное право

- **GIVEN** админ отключил право «подтверждение отмены» для роли editor
- **WHEN** editor пытается confirm-cancel
- **THEN** 403 с объяснением («право отключено админом»)

#### Scenario: Выдача права видна в журнале

- **GIVEN** админ сменил права роли/участника
- **WHEN** он открывает журнал изменений прав
- **THEN** видно кто, когда и что поменял

### Requirement: Проверка прав на каждом действии

Каждое изменяющее действие SHALL проходить проверку прав текущего пользователя в контексте текущего workspace; недостаток прав — 403 с идентификатором недостающего права в теле ответа.

#### Scenario: Недостаток прав

- **GIVEN** reader и ручка PUT /tasks/{id}/priority
- **WHEN** запрос выполнен
- **THEN** 403 с указанием требуемого права («правки приоритетов»)

### Requirement: Роли и права локальные по workspace

Права действуют в границах workspace-а: роль пользователя в одной компании MUST НЕ давать прав в другой (роль MAY различаться по workspace-ам); наследования прав между workspace-ами нет.

#### Scenario: Роль не распространяется между компаниями

- **GIVEN** пользователь X — admin в workspace A, reader в workspace B
- **WHEN** X вызывает админ-действие в B
- **THEN** 403 — права считаются по роли в B
