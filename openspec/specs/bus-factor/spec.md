# Bus Factor — зависимость от отдельных носителей компетенций

## Purpose

Bus Factor отражает зависимость работы от отдельных носителей компетенций: пользователь видит, где отсутствие одного сотрудника создаёт риск для выполнения работ. Расчёт по областям, для которых считается показатель (команды / отдельные компетенции) по данным `engineers_profiles.csv`. Конкретную методику и допущения команда договорится после созвона и зафиксирует через change proposal — пока фиксированы рамки из задания.

## Requirements

### Requirement: Расчёт Bus Factor

Сервис SHALL рассчитывать Bus Factor по компетенциям на основе ролей и заявленных навыков инженеров.

#### Scenario: Компетенция с носителем

- **GIVEN** несколько инженеров владеют компетенцией «Java»
- **WHEN** пользователь смотрит Bus Factor компании
- **THEN** для этой компетенции отображается число носителей

### Requirement: Объяснение методики

Сервис SHALL объяснять используемую методику расчёта Bus Factor и область, для которой рассчитывается показатель (команда / роль / вся компания).

#### Scenario: Справка о методике

- **WHEN** пользователь открывает раздел Bus Factor
- **THEN** рядом с показателем видна формулировка методики и область расчёта

### Requirement: Риск одиночной зависимости

Сервис SHALL выделять случаи, когда уход одного сотрудника создаёт риск для планируемых работ: компетенции с единственным носителем в области.

#### Scenario: Уникальный носитель роли

- **GIVEN** в Team-L роль «Дизайнер» имеет только одного носителя (ENG-405, 0.5 ставки)
- **THEN** для Team-L отображается отметка одиночной зависимости по этой роли

### Requirement: Риски в терминах планирования

Сервис SHALL связывать риски Bus Factor с планированием: показывать, какие задачи квартального плана затронутых компетенций оказываются под угрозой.

#### Scenario: Задача под угрозой

- **GIVEN** на задачу требуются часы роли с единственным носителем
- **WHEN** пользователь смотрит риск
- **THEN** виден список задач, зависящих от этого носителя

### Requirement: Риски плана в терминах задач

Сервис SHALL сопоставлять риски Bus Factor с задачами запланированного плана: единая ручка возвращает задачи, затронутые компетенциями/ролями с единственным носителем, для виджета дашборда (user flow v0.4, стр. 1).

#### Scenario: Виджет дашборда

- **WHEN** фронтенд открывает дашборд плана
- **THEN** виджет «N задач под угрозой» берёт данные из одной ручки (без склейки /bus-factor и role_hours на фронте)
