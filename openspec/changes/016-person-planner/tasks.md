## 1. Назначения по людям (planner)

- [ ] 1.1 Модель назначения: task × role × engineer × sprint (в plan item: engineer/role по каждой части разбитой задачи) — хранение в версии плана
- [ ] 1.2 Планировщик назначает носителей ролей задачам (заём включён), ёмкость 80/40 по инженеру за спринт (суммарно по командам для parttime)
- [ ] 1.3 Назначения в ответе GET /plans/{id} (добавление, без break старых полей)
- [ ] 1.4 Тест PDF-примера: DB-202 (один носитель роли, 130 ч) — тот же человек в спринтах 1 и 2 (80+50), одна полоса

## 2. Личный план и порядок (api)

- [ ] 2.1 GET /plans/{id}/people/{engineer_id}: личная очередь по спринтам (упорядоченная, закреплённые помечены); 404 нет плана, пусто для незадействованного
- [ ] 2.2 Ручки pin/unpin: POST /plans/{id}/tasks/{tid}/pin {sprint_no, engineer_id?} / DELETE; 409 на конфликтный pin (занятая ёмкость), 404 нет объекта
- [ ] 2.3 Фиксация позиции личного порядка через pin (поз. или несколько)
- [ ] 2.4 Тесты: личный план ENG-405; pin сохраняется при пересчёте (pre-occupancy); соседние сдвиги в diff с причинами

## 3. Конфликты pin (planner)
