## Context

Система работает в номерах спринтов 1..6; дат квартала нет. В dataset есть даты задач (`planned_start/planned_end/actual_end`), но заполнены частично. Снапшот-цепочка планов и метрики от initial-плана уже реализованы (изменение 003/архив). Итог текущих договорённостей: решение №12 (старт квартала от дат датасета), №10 (часы ролей в факте — опционально), №8 (грейд-warning).

## Goals / Non-Goals

**Goals:**
- Детерминированный календарь квартала (6 × 2 недели) с датами, производный от датасета (решение №12)
- Прогнозные интервалы дат у задач и предупреждения с датами (`deadline_overflow`)
- Возврат дат в API без ломки контракта (только новые поля)

**Non-Goals:**
- Перевод planner на даты как первичные величины (SP/часы остаются гейтами; даты — проекция)
- Рабочие/производственные календари, праздники
- Изменение математика метрик

## Decisions

- **Спринты = 14 дней подряд, без буферов/выходных-календарей** — самая простая детерминированная модель, объяснимо в README; альтернатива (рабочие дни × 8ч) усложняет честные часы и не нужна для демо
- **Календарь хранится в плане** (`PlanORM` дополнительные поля quarter_start/sprint_length_days): версии плана наследуют календарь предка — при пересчётах квартал не «двигается»; изменение календаря — только явным действием
- **Неполнота дат в tasks.csv**: max(planned_end) считается только по непустым датам; fallback — фактические даты; если дат нет вообще — календарный квартал от текущей даты (спека фиксирует этот fallback)
- **role_hours_fact** — опциональное поле без миграции в план-версию: факт хранится в SprintFactORM (JSON), используется отображениями предупреждений; не входит в дельту SP (два гейта остаются)
- **grade_deficit — warning, не гейт**: подтверждение решения №8; «самый младший грейд» определяется по датасету (минимальный пронумерованный грейд в командах, напр. Junior)

## Risks / Trade-offs

- Спринт 2 недели всегда — может не совпасть с реальными календарями команд; trade-off принят (простота/воспроизводимость)
- Новый JSON-блок факта: старые тесты в 409/новые поля — не ломают совместимость — проверяются тестами
