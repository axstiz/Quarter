# Change: 011-references-and-hours (spec-only)

## Why

В датасете есть два файла, которые текущий importer только **проверяет на наличие**, но не импортирует и не использует:

1. **reference_values.csv** (19 справочных строк: итоги разработки, причины расхождения планов, результаты закрытия задач) — а по заданию сервис должен объяснять причины расхождения планов; справочные категории прямо для этого.
2. **task_role_hours.csv** (фактические часы по ролям, 6 задач) — README обещает «используется для расчёта фактической производительности по ролям», но ни спека, ни код этого не делают.

Также importer не импортирует его в БД (список FILES только валидирует наличие). Спека фиксирует баланс: что импортируется и где используется.

## What changes

1. **data**: importer импортирует reference_values.csv в таблицу справочников (idempotent per import, source=imported); task_role_hours.csv импортируется как фактическая разбивка по ролям.
2. **api**: карточка задачи (task detail / plan-объект) показывает фактические часы по ролям (task_role_hours), где они есть — витринно.
3. **replanning**: объяснения расхождений планов SHALL опираться на справочные категории причин (reference_values) — в reason/warning виден понятный класс причины.

## Non-goals

- Задача: task_role_hours **не участвует** в планировании (planner не трогается) — только витрина. (Фактическая производительность по ролям остаётся допущением README, без расчётов на 6 задач.)
- Правки dataset/*.csv / split_dataset.py — не нужны (файлы уже корректны).
- Реализации в этом change нет (spec-only).

## Risks

- Справочные категории — русские формулировки из датасета; показываются как есть (перевод/канонизация не в этот change).
- Новая таблица → затронут reset/import-совместимость (справочники — импортная таблица: их язык отражён в согласованном фикс-изменении reset_dataset_tables).
