# Update capability: data

## ADDED Requirements

### Requirement: Импорт справочников

Importer SHALL импортировать `dataset/reference_values.csv` в таблицу справочников (типа: итоги разработки, причины расхождения планов, результаты закрытия задач) при POST /data/import; повторный импорт обновляет справочники целиком (source=imported, ручных правок справочников не предусмотрено в MVP).

#### Scenario: Импорт датасета включает справочники

- **GIVEN** dataset полный (7 файлов)
- **WHEN** POST /api/v1/data/import
- **THEN** counts содержит "reference_values": 19; повторный импорт даёт тот же состав (idempotent)

### Requirement: Импорт фактических часов по ролям

Importer SHALL импортировать `dataset/task_role_hours.csv` (фактические часы по ролям для задач, где данные есть) — витринно: карточка задачи показывает фактическую разбивку часов по ролям; данные НЕ участвуют в планировании (решение: planner не меняется).

#### Scenario: Карточка задачи с фактическими часами

- **GIVEN** задача из шести с фактическими разбивками по ролям
- **WHEN** GET /tasks/{task_id}
- **THEN** ответ содержит фактические часы по ролям (role_hours_actual); для задач без данных — поле отсутствует/пустое

# Update capability: replanning

## ADDED Requirements

### Requirement: Причины расхождений из справочников

При формировании объяснений расхождения планов (по факту спринта) сервис SHALL привязывать объяснение к справочной категории причин из `reference_values.csv` (импорт capability data): пользователь видит понятную формулировку причины (дата из справочника), а не только технический diff.

#### Scenario: Расхождение с понятной причиной

- **GIVEN** факт спринта показал недобор SP
- **WHEN** пользователь смотрит объяснения пересчёта
- **THEN** рядом с технической причиной указан справочный класс причины расхождения (например «недостаток времени роли», «повышение сложности задач» — формулировка из датасета)
