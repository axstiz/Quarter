# Proposal: 047-plan-ui-fixes

## Why

Ручная проверка плана нашла шесть замечаний, пять из которых сводятся к трём корневым причинам:

1. **Несколько строк одной задачи в одном спринте.** Оптимизатор режет задачу на части без ограничения «разные части — в разные спринты», а `pin_task` сваливал в целевой спринт все строки задачи. Отсюда «2 задачи №X 1/2» и дубли чипов в «Ролях по спринтам», «групповые» отметки в «Факте спринта» (состояние по `task_id`), коллизии React-ключей.
2. **Несуществующие CSS-переменные** (`--surface`, `--accent`) у вуали оптимизации — всегда белый фолбэк, тёмная тема на экран не применяется; легенда звёздной карты зафиксирована на светлых хексах.
3. **Края полосы Ганта через `:first-child`/`:last-child`**, а не через границы непрерывных отрезков — у задачи с паузой или частичной задачи внутри полосы появлялась «вторая обводка».

Плюс продуктовые пункты: палитра решений расходилась со спекой (planned был синим, факт — зелёным) и список «не влезают» не был доступен рядом с вкладками.

## What Changes

- **Бэк:** `PinRequest.from_sprint_no` — перенос одной части задачи (только строка из этого спринта), остальные части на местах. После переноса строки задачи в целевом спринте сливаются в одну (SP суммируются, assignments конкатенируются с новым `sprint_no`), `pinned_sprint` — у пережившей строки. `unpin` снимает закрепление со всех частей задачи. Без `from_sprint_no` — прежнее поведение (вся задача).
- **Фронт, модель плана:** защитное слияние строк одной задачи внутри спринта — одна строка на (задача × спринт); нумерация частей, чипы ролей и отметки факта считаются корректно.
- **Фронт, «Роли по спринтам»:** перетаскивание передаёт `from_sprint_no`; отказ сервера запоминается по части (`задача:из:в`).
- **Фронт, «Факт спринта»:** ключ строки `task_id|sprint_no`, «Отметить все» и счётчики — по уникальным задачам.
- **Фронт, Гант:** сегмент получает `data-cap` (`start|end|both|mid`) по непрерывному отрезку; у частичной задачи открыт только правый край последнего сегмента.
- **Фронт, цвета:** вуаль/карточка на `--sheet`/`--ink`/`--plan`; `planned` → зелёный (`done`), `done_actual` → серый (новый токен `--fact`); легенда звёздной карты берёт цвета канваса; «прогноз» в метриках — единый нейтральный бейдж; низкий риск прогноза — зелёный, как благополучный Bus Factor. Статический тест: каждый `var(--x)` определён в `tokens.css`.
- **Фронт, «Не влезают · N»:** кнопка справа от вкладок плана открывает панель: вне квартала (без отменённых) и влезли частично.

## Capabilities

### Modified Capabilities

- `planning` — закрепление (pin) части задачи; одна строка на (задача × спринт) после переноса.
- `ui` — единый редактор раскладки переносит часть из ячейки; палитра решений по спеке; список «не влезают».

## Impact

`src/domain/models.py` (`PinRequest`), `src/api/routes.py` (`pin_task`, `unpin_task`), `tests/test_pin_part.py`; фронт: `planModel.ts`, `GanttView.tsx`, `RolesView.tsx`, `PlanPage.tsx`, `NotFitPanel.tsx`, `SprintFactPage.tsx`, `MetricsPage.tsx`, `ForecastTab.tsx`, `StarMap*.tsx`, `Badge.tsx`, `Tabs.tsx`, `tokens.css`, `components.css`, `frontend/tests/css-tokens.test.mjs`.

Ограничение: пересчёт (`recompute`) по-прежнему читает пины на уровне задачи — задача с закреплённой частью при пересчёте ставится в спринт пина целиком (как до 047).
