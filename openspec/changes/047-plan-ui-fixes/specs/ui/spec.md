# Update capability: ui

## MODIFIED Requirements

### Requirement: Статусы различимы не только цветом

UI SHALL визуально различать decision (planned/postponed/cancelled_pending/cancelled/done_actual) так, чтобы цвет не был единственной индикацией (иконка/текст/подпись тоже). Тон решения SHALL быть единым во всех видах (Гант, «Роли по спринтам», бейджи, легенды): `planned` — зелёный, `postponed` — жёлтый, `cancelled_pending` — оранжевый, `cancelled` — красный, `done_actual` — серый. Синий акцент интерфейса (кнопки, вкладки, фокус, ссылки, шкалы загрузки) статусом не является. Цвета SHALL браться из токенов темы, чтобы светлая и тёмная темы применялись ко всем экранам, включая вуаль оптимизации и легенду звёздной карты.

#### Scenario: Задача у дальтоника

- **GIVEN** задаче запланирован зелёный цвет и planned
- **WHEN** пользователь смотрит колонку спринта
- **THEN** статус задачи различим без восприятия цвета

#### Scenario: Факт и план в одной полосе

- **GIVEN** задача выполнена по факту в спринте 1 и запланирована в спринте 2
- **WHEN** пользователь смотрит Гант
- **THEN** сегмент спринта 1 серый с пометкой «выполнена», сегмент спринта 2 зелёный с долей SP

#### Scenario: Тёмная тема на экране оптимизации

- **GIVEN** включена тёмная тема
- **WHEN** идёт оптимизация плана
- **THEN** вуаль и карточка прогресса тёмные, индикатор — цвет акцента

### Requirement: Единый редактор раскладки

Ручное редактирование раскладки (переносы частей задач между спринтами) SHALL выполняться только в виде «Роли по спринтам»; Гант по задачам SHALL оставаться read-only по раскладке. Перетаскивание чипа роли SHALL переносить **часть задачи из этой ячейки** (её SP и часы всех ролей), остальные части задачи остаются на своих спринтах. Отпускание чипа вызывает `POST /plans/{id}/tasks/{task_id}/pin {sprint_no, from_sprint_no}` — сервер перемещает часть немедленно (change 039) и сливает её с частью, уже стоявшей в целевом спринте; фронт перечитывает план: из старой колонки элемент исчезает, в целевой — один чип задачи, без дублирования, optimistic-слоёв, бейджей и баннеров. Нумерация частей после переноса последовательна (1/2, 2/2). Конфликт ёмкости/зависимости (409) отклоняется с текстом причины, чип остаётся на месте, повтор той же части на ту же цель заблокирован (другие части задачи переносить можно); «Вернуть» — `DELETE /plans/{id}/tasks/{task_id}/pin` снимает закрепление задачи целиком. Клиентские хранилища раскладки для переносов не используются. Раскладка SHALL быть синхронной между видами «Роли по спринтам» и «Диаграмма Ганта». Недопустимые цели (спринт зафиксирован фактом, вне квартала) MUST отклоняться на клиенте до вызова пина с текстом причины.

#### Scenario: Оптимистичный перенос

- **GIVEN** пользователь перетаскивает чип роли задачи из спринта 2 в спринт 4
- **WHEN** POST pin успешен
- **THEN** после перечитывания плана чип в спринте 4, SP/часы колонок 2 и 4 пересчитаны; соседние задачи стоят на месте; optimistic-слоёв и бейджей нет

#### Scenario: Оптимистичный перенос отклонён сервером

- **GIVEN** pin вернул 409/ошибку
- **WHEN** onError
- **THEN** чип остаётся в исходной колонке, причина видна, повтор этой части на ту же цель заблокирован; другие части задачи переносить можно

#### Scenario: Недопустимая цель

- **GIVEN** целевой спринт зафиксирован фактом / вне квартала
- **WHEN** пользователь отпускает чип
- **THEN** перенос отклонён на клиенте с текстом причины, POST не отправлялся

#### Scenario: Немедленный перенос через пин

- **GIVEN** задача частями размещена в спринтах 2 и 3, backend доступен
- **WHEN** пользователь перетаскивает чип роли из спринта 2 в спринт 4
- **THEN** фронт вызывает POST pin `{sprint_no: 4, from_sprint_no: 2}`; сервер перемещает часть немедленно, без пересборки версии

#### Scenario: Конфликт ёмкости на живом бэке

- **GIVEN** целевой инженер в спринте 4 уже загружен (лимиты заняты)
- **WHEN** POST pin
- **THEN** 409 с текстом «нужно X ч, свободно Y ч», часть не перемещается

#### Scenario: Возврат переноса

- **WHEN** пользователь нажимает «Вернуть»
- **THEN** вызывается DELETE pin (без пересборки) — закрепление снимается с задачи целиком; раскладка частей остаётся, при пересчёте задача расставляется планировщиком

#### Scenario: Перенос части задачи из вида ролей

- **GIVEN** задача частями размещена в спринтах 2 и 3
- **WHEN** пользователь перетаскивает её чип роли из спринта 2 в спринт 4
- **THEN** часть из спринта 2 целиком переезжает в спринт 4 — все её ролевые чипы и SP, в этом виде и на «Диаграмме Ганта»; часть в спринте 3 на месте, нумерация частей последовательна

#### Scenario: Перенос в спринт с другой частью

- **GIVEN** задача частями размещена в спринтах 2 и 3
- **WHEN** пользователь перетаскивает чип из спринта 3 в спринт 2
- **THEN** в спринте 2 один чип задачи с суммой часов, задача больше не делится на части

#### Scenario: Синхронность видов

- **GIVEN** часть задачи перенесена пином в спринт 5
- **WHEN** пользователь открывает «Диаграмму Ганта»
- **THEN** та же часть отображается в спринте 5, статистика SP и загрузка ролей пересчитаны

#### Scenario: Баннер неприменённых пинов

- **GIVEN** есть закрепления
- **WHEN** пользователь видит редактор раскладки
- **THEN** баннера неприменённых пинов нет (пин применяется немедленно, change 039); доступно действие «Сбросить закрепления · N»

#### Scenario: Перенос части задачи — без немедленной пересборки

- **GIVEN** задача частями размещена в спринтах 2 и 3
- **WHEN** пользователь перетаскивает её чип роли из спринта 2 в спринт 4
- **THEN** версия плана не пересобирается: двигается только эта часть, соседние задачи стоят на месте

## ADDED Requirements

### Requirement: Список «не влезают» рядом с вкладками плана

На всех вкладках страницы плана при наличии задач, не помещающихся в квартал целиком, справа от вкладок SHALL показываться действие «Не влезают · N» (N = вне квартала без отменённых + влезли частично). Действие открывает боковую панель с двумя секциями: «Вне квартала» (решение, причина, команда, SP) и «Влезли частично» (спринты размещения, остаток SP за кварталом). Строка открывает карточку задачи.

#### Scenario: Открытие списка

- **GIVEN** в плане 3 задачи вне квартала и 2 частичные
- **WHEN** пользователь нажимает «Не влезают · 5» на вкладке «Роли по спринтам»
- **THEN** открывается панель с секциями «Вне квартала · 3» и «Влезли частично · 2»; клик по строке открывает карточку задачи

#### Scenario: Всё влезло

- **GIVEN** все задачи плана помещаются в квартал целиком
- **THEN** действия «Не влезают» нет

### Requirement: Отметка факта по задаче

Экран «Факт спринта» SHALL показывать одну строку на задачу спринта; клик по строке отмечает ровно эту задачу; «Отметить все» переходит в состояние «отмечены все», когда отмечены все задачи спринта; счётчики «отмечено» и «вернутся в планирование» считаются по задачам.

#### Scenario: Отметить все

- **GIVEN** в спринте 5 задач, одна из них — часть разбитой задачи
- **WHEN** пользователь нажимает «Отметить все»
- **THEN** флажок в заголовке в состоянии «отмечено», «Отмечено 5 из 5»
