# Change: 013-metric-driven-order (spec-only)

## Why

Инструмент должен «расставить приоритеты на основе скоринга, чтобы спасти стратегически важные инициативы» (подсказка PDF Демо_онбординг, раздел 5). Сейчас планировщик сортирует задачи только по полю priority (human seed), а целевые KPI из PDF (PI Predictability норма 80–100%, Say/Do 90–105%) считаются, но не показывается «в норме или нет», и никем не оптимизируются. Решение лида (2026-09-17): **метрики первичны, приоритет вторичен**; оба механизма (сортировка задач под метрики + рекомендации перераспределения людей) human-in-loop, как режимы на выбор — дефолт (priority) не меняется, ноль breaking change.

## What changes

1. **planning** (ADDED): метрическая стратегия планирования (`strategy` на генерации плана: `metrics | priority`; дефолт `priority`) — при `metrics` порядок задач определяется целевой функцией: (1) стратегические задачи (флаг заказчика `planned_in_sprint=Да`, PRODF) первыми; (2) затем задачи, замыкающие инициативы до конца квартала (дающие числитель KPI №1); (3) далее остальное по потенциалу частичного закрытия; поле priority — только тайбрейкер внутри равных групп. В reason плановых задач отмечается применение стратегии.
2. **planning** (ADDED): рекомендации перераспределения людей — симуляции переноса долей ставок инженеров между командами с расчётом влияния на метрики плана; человек применяет совет сам (правка инженера через CRUD + пересчёт), автоприменения нет. Рекомендации НЕ предлагают перенос носителей единственных компетенций (защита Bus Factor ≤ 1).
3. **api** (ADDED): `POST /plans/generate` принимает опциональный `strategy`; `GET /plans/{plan_id}/optimization-report` — сравнение метрик плана с приоритетным эталоном; `GET /plans/{plan_id}/staffing-suggestions` — список симуляций по людям с ожидаемым эффектом.
4. **metrics** (ADDED): целевые нормы KPI из PDF — PI Predictability норма 80–100 %, Say/Do 90–105 %; показатели несут `target_band` и признак соответствия норме; фиксируется соответствие терминов: «Неделя 0» (PDF) = initial-план (снапшот-цепочка).

## Non-goals

- Реализации в этом change нет (spec-only) — изменение отдельным change по tasks.md.
- Автоматическое применение рекомендаций по людям без подтверждения человека.
- Оптимизатор полного перебора/MILP — детерминированная жадная эвристика, воспроизводимость строже точности.
- Изменение дефолтного режима: существующие тесты/контракт фронта не меняются.

## Risks

- Метрическая сортировка может выглядеть как «игра с знаменателем» (включать в initial-план только лёгкие инициативы) — спека запрещает управление знаменателем: включение задач в план определяется только емкостью и зависимостями, скоринг влияет на порядок, не на состав.
- Деградация без рекомендаций: staffing-suggestions при пустых данных отдаёт пустой список (без hard-fail).
