# Change: 023-bus-factor-enhancements

## Why

Статический Bus Factor отвечает «сколько носителей у компетенции», но не отвечает на вопрос лида «где у нас будут проблемы в будущем»: инженер может быть один носителем роли и одновременно таскать большой объём плановой работы — потеря такого человека бьёт по плану сильнее, чем из запасной компетенции. Данные для прогноза уже есть в версиях плана: assignments (task × роль × инженер × спринт × часы, change 016, теперь и в solver-версиях — 022). Решение лида (2026-09-21): прогноз строится **по плановой загрузке** — объём задач и часов, закреплённых за человеком, плюс критичность его ролей (единственный носитель) и перегрузка спринтов.

## What Changes

1. **Прогноз по загрузке** (bus-factor, ADDED): ручка `GET /plans/{plan_id}/bus-forecast` — по каждому инженеру с плановой загрузкой: часы по спринтам (из assignments, лимит 80×ставка), всего задач/часов, роли, где он единственный носитель (company-scope, как plan_bus_risk), перегруженные спринты; прогноз-оценка `если носитель уйдёт: N задач / M часов под угрозой` с уровнем риска (high/medium/low) и численным основанием. Методика прикладывается в ответе.
2. **Вкладка на звёздной карте** (ui, ADDED): «Прогноз рисков» — таблица людей: загрузка по спринтам (мини-бары к лимиту), критичные роли, уровень риска с основанием, «если уйдёт: N задач / M ч»; переход в профиль инженера. Пустое состояние — «плана нет / загрузки нет».
3. **Моки**: имитация ручки — детерминированная раскладка role_hours по носителям (расхождение с бэком №10 documented: assignments в моке не хранятся).

### Modified Capabilities

- `bus-factor`: ADDED «Прогноз bus factor по плановой загрузке» (ручка + методика).
- `ui`: ADDED «Вкладка прогноза рисков» (звёздная карта, вход в профиль инженера).

## Non-goals

- Invite участников / токены приглашений — отложено (могу оформить позже, вне сдачи).
- Такcономия родительских ролей («Тестировщик (Автотестирование)» → «Тестировщик») — отброшено по решению лида (2026-09-21): эвристика по строкам не обоснована данными задачи-навыка.
- Team-scope в `plan_bus_risk` — не трогаем: существующая company-область сохраняет обратную совместимость поля.
- Изменения arbiter'а планировщика и Java-модели.
