# Proposal: 038-pin-optimistic-ui

## Why

После change 032 (пин = намерение, без немедленной пересборки) оптимизмическая вisualка фронтэndа отсутствует: чип остаётся в старой колонке, SP/часы не меняются, видна только плашка/баннер — по решению лида задача должна сразу появляться в целевой колонке с пересчитанными SP/часами локально (optimistic слой), с бейджем «пин» до пересчёта.

## What Changes

- Оптимистичный слой пинов на уровне плана (PlanPage, меняется модель до `buildRoleModel`): у задачи меняется `sprint_no` части на целевой спринт — весь downstream-расчёт (колонки, SP-суммы, часовые метры) работает как на уже переехавшей задаче, в обоих видах (синхронность «Роли»/Гант)
- Перемещённый чип помечается бейджем «пин» (ожидает пересчёт); старая колонка теряет SP/часы немедленно
- Сброс слоя: после «Пересчёта»/загрузки факта (серверная раскладка поступает через invalidate) и при смене версии плана; при 409 pin слой не двигается (frigation через failedPins)

## Capabilities

### Modified Capabilities

- `ui` — «Единый редактор раскладки»: перемещение чипа SHALL отображаться немедленно в целевой колонке (подле «пин» — пин ожидает пересчёта), SP и часы колонок пересчитываются локально; итоговая раскладка после пересчёта.

## Impact
`frontend/src/features/plan/PlanPage.tsx` (state+модель), `frontend/src/features/plan/RolesView.tsx` (badge/kulback); backend остаётся по change 032.
