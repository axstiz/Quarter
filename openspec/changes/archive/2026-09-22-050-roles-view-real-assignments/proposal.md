# Proposal: 050-roles-view-real-assignments

## Why

Вкладка «Роли по спринтам» показывала хлам: `buildRoleModel` игнорировал реальные назначения бэкенда (`assignments` в ответе плана) и пересчитывал часы сам — `role_hours всей задачи × SP-доля части`. Это заново создавало осколки (50 чипов <1 ч: роль 1 ч × доля 0.33 = 0.33 ч), выдуманные дорожки займа (своя логика «наибольший свободный лимит», расходится с 045/046), дубли чипов «1/2» и «2/2» в одной ячейке (две части в одном спринте). Итог: 626 чипов, из которых значимая часть — артефакты пересчёта.

## What Changes

- `buildRoleModel`: чипы строятся из `row.assignments` (реальные инженер × роль × часы, посчитанные бэкендом `_put_hours`): дорожка = команда инженера, `loan` = команда инженера ≠ владелец задачи, `VIRTUAL-*` → дефицит в дорожке владельца
- Агрегация: один чип на (дорожка, задача, роль, заём) — склеиваются назначения нескольких инженеров и дубли частей одного спринта; чип показывает число инженеров
- `part/parts` чипа — по разным спринтам задачи, не по числу строк плана
- Fallback для строк без назначений (done_actual старых версий) — прежняя логика сохранена
- `types.ts`: `PlanAssignment`, `PlanTask.assignments`
- QA на живом оптимизированном плане: чипов 626 → 425 (−32%), часы по спринтам совпадают (±1%), осколки <1 ч из пересчёта устранены (остались только реальные остатки лимитов)

## Capabilities

### Modified Capabilities

- `planning` — «Роли по спринтам» отображают реальные назначения бэкенда, без повторного пересчёта на фронте.

## Impact
`frontend/src/lib/roleModel.ts`, `frontend/src/api/types.ts`. Бэк не тронут.
