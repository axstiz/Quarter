# Change: 006-ui (spec-only)

## Why

Фронтендер начинает разработку (user flow v0.4 — docs/product-plan.md). Контракт API у него уже есть (`docs/api-contract.md`, `openapi.json`), но поведенческие правила UI нигде не зафиксированы: какие решения обязаны носить подпись «прогноз», что показывается рядом с причиной, как ведёт себя UI после факта спринта. Спека фиксирует поведение задолго до кода — change spec-only, без реализации.

## What changes

Новая capability `ui` (~9 требований): причины решений всегда видны; цвет = не единственная индикация статуса; приоритеты — за человеком; двухшаговая отмена; переключение на новую версию плана после факта; показ рисков со списком задач; метрики с обязательной подписью факт/прогноз; звёздная карта с фильтрами и подсветкой; методика Bus Factor рядом с показателем.

## Non-goals

- Дизайн, layout, стек фронта (React/…), библиотеки графов — за фронтендером.
- Код UI в этом change нет: реализация — по tasks.md в change 006 после старта фронтендера.
- Виджет Bus-риска: ручка уже есть (change 004) — спека фиксирует только обязательность виджета-данных из одной ручки.

## Risks

- Спека полностью без кода: риск дрейфа между спекой и реальным фронтом закрывается ревью change при реализации.
