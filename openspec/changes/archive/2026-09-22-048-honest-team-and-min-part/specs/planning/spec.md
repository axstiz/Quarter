# Update capability: planning

## ADDED Requirements

### Requirement: Минимальный размер части роли при pre-split

При разбиении задачи на части (pre-split для solver) сервис SHALL NOT дробить роль на части мельче 2 часов (`MIN_ROLE_PART_HOURS`): если доля роли в части меньше минимума, все часы этой роли назначаются последней части целиком. Роли с долей не меньше минимума делятся пропорционально доле части. Сумма часов роли по частям SHALL сохраняться.

#### Scenario: Мелкая роль не дробится

- **GIVEN** задача на 191 ч с ролями Разработчик 190 ч и Девопс 1 ч (k=3 части)
- **WHEN** pre-split
- **THEN** Девопс 1 ч целиком в части 3; части 1–2 не содержат Девопс; Разработчик делится пропорционально

#### Scenario: Роль выше порога дробится пропорционально

- **GIVEN** задача на 160 ч с ролями Разработчик 150 ч и Тестировщик 10 ч (k=2 части)
- **WHEN** pre-split
- **THEN** обе роли делятся пропорционально доле части; каждая часть Тестировщика ≥ 2 ч

### Requirement: Честная атрибуция команды-исполнителя в API плана

Элемент плана в ответе API SHALL содержать `team_id` команды-исполнителя части (solver может назначить часть другой команде) и `owner_team_id` команды-владельца задачи. Таблицы загрузки по командам SHALL группироваться по команде-исполнителю, чтобы SP атрибутировались той команде, чья ёмкость реально потребляется.

#### Scenario: Часть исполняет другая команда

- **GIVEN** solver назначил часть задачи T-1 (владелец Team-A) команде Team-B
- **WHEN** GET /plans/{id} оптимизированной версии
- **THEN** элемент T-1 содержит team_id=Team-B и owner_team_id=Team-A
