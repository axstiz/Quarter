# Update capability: ui

## MODIFIED Requirements

### Requirement: Единый редактор раскладки

Ручное редактирование раскладки (переносы частей задач между спринтами) SHALL выполняться только в виде «Роли по спринтам»; Гант по задачам SHALL оставаться read-only по раскладке. Перетаскивание чипа роли SHALL двигать часть задачи целиком (включая SP, часы и остальные роли части). Отпускание чипа вызывает `POST /plans/{id}/tasks/{task_id}/pin {sprint_no, engineer_id?}` — **пин фиксируется как намерение (change 032): пересборка версии НЕ выполняется, соседние чипы сразу не сдвигаются**; применённых к раскладке пин получает при следующем пересчёте (POST /plans/{id}/recompute или авто-пересчёт после факта спринта, через pre-occupancy). Элемент с неприменённым пином SHALL отмечаться меткой «закреплено (ожидает пересчёт)»; наличие неприменённых закреплений SHALL отражаться баннером с действием «Пересчитать». Конфликт ёмкости/зависимости (409/422) отклоняется с текстом причины; «вернуть» — `DELETE /plans/{id}/tasks/{task_id}/pin` (также без пересборки). Клиентские хранилища раскладки (localStorage по planId, in-memory override-слои) для переносов не используются; переносы работают на живом бэкенде, а не только в мок-режиме. Раскладка SHALL быть синхронной между видами «Роли по спринтам» и «Диаграмма Ганта» (единая раскладка читается из плана). Недопустимые цели (спринт зафиксирован фактом, вне квартала, в целевом спринте уже есть другая часть той же задачи) MUST отклоняться на клиенте до вызова пина с текстом причины. Границы версий (advanced контекст) сохраняются через план-версии.

#### Scenario: Перенос части задачи — без немедленной пересборки

- **GIVEN** задача частями размещена в спринтах 2 и 3
- **WHEN** пользователь перетаскивает её чип роли из спринта 2 в спринт 4
- **THEN** пин зафиксирован ( намetренность: спринт 4), соседние чипы не сдвигаются немедленно, на элементе метка «закреплено (ожидает пересчёт)»; после «Пересчёте»/факта часть целиком переезжает: все её ролевые чипы и SP переносятся в спринт 4 в этом и в виде «Диаграмма Ганта»

#### Scenario: Недопустимая цель

- **GIVEN** целевой спринт зафиксирован фактом / вне квартала
- **WHEN** пользователь отпускает чип
- **THEN** перенос отклонён на клиенте с текстом причины, POST не отправлялся

#### Scenario: Баннер неприменённых пинов

- **GIVEN** есть ≥1 закрепление, чей целевой спринт отличается от текущей расстановки
- **WHEN** пользователь видит редактор раскладки
- **THEN** баннер «Есть N закреплений, не применённых к плану — Пересчитать», действие открывает пересчёт

#### Scenario: Перенос части задачи из вида ролей

- **GIVEN** задача частями размещена в спринтах 2 и 3
- **WHEN** пользователь перетаскивает её чип роли из спринта 2 в спринт 4 и затем нажимает «Пересчитать»
- **THEN** после пересчёта часть целиком переезжает: все её ролевые чипы и SP переносятся в спринт 4 в этом и в виде «Диаграмма Ганта»

#### Scenario: Немедленный перенос через пин

- **GIVEN** задача частями размещена в спринтах 2 и 3, backend доступен
- **WHEN** пользователь перетаскивает чип роли из спринта 2 в спринт 4
- **THEN** фронт вызывает POST pin {sprint_no: 4}; пин фиксируется как намерение (без пересборки версии), появляется тост «закреплено · снять», а после пересчёта (кнопка/факт) часть задачи размещается в спринте 4

#### Scenario: Конфликт ёмкости на живом бэке

- **GIVEN** целевой инженер в спринте 4 уже загружен (лимиты заняты)
- **WHEN** пересчёт выполнен
- **THEN** конфликт отразится предупреждением/сдвигом по pre-occupancy спеки planning (PIN не влезает); раскладка не нарушает hard-правил

#### Scenario: Возврат переноса

- **WHEN** пользователь нажимает «снять закрепление» в тосте после переноса
- **THEN** вызывается DELETE pin (без пересборки), задача планируются на общих основаниях при следующем пересчёте

#### Scenario: Синхронность видов

- **GIVEN** часть задачи закреплена в спринте 5 пином и план пересчитан
- **WHEN** пользователь открывает «Диаграмму Ганта»
- **THEN** та же часть отображается в спринте 5, статистика SP и загрузка ролей пересчитаны
