# Update capability: planning

## MODIFIED Requirements

### Requirement: Закреплённые назначения (pin) — жёсткие якоря

Человек MAY закрепить (pin) назначение (задача–человек–спринт) и/или позицию. Pin SHALL быть немедленным намерением: закрепление записывается в текущую версию плана (pinned-метаданные) БЕЗ немедленной пересборки плана; ближние задачи не сдвигаются. Применение закреплённого к раскладке (pre-occupancy) SHALL происходить при явном POST /plans/{id}/recompute и автоматическом пересчёте после факта спринта — а не при pin/unpin. Лёгкие валидации при закреплении сохраняются: спринт в границах квартала, факт-спринт закрыт, конфликт с зависимостью закреплённого блокера — 409. Конфликты дробной поведения по прежнему видны при пересчёте (compute_warnings; грейд- и дефицит-предупреждения), молчаливый сдвиг закреплённого исключён. Снятие pin — человеческое действие (unpin), также без пересборки.

#### Scenario: Пересчёт вокруг pin

- **GIVEN** задача A закреплена (спринт 2, инженер E); после факта спринта 1 у Team-L изменилась нагрузка
- **WHEN** пересчёт (факт или кнопка)
- **THEN** A остаётся в спринте 2 у того же инженера (pre-occupancy); незакреплённые задачи планируются на остатке ёмкости; соседние сдвиги отражены в diff с причиной

#### Scenario: Перетащил — соседи не уехали

- **GIVEN** план построен, пользователь перетащил задачу A в спринт 3 (pin)
- **WHEN** POST pin успешен
- **THEN** новая версия НЕ создаётся, соседние задачи не сдвигаются немедленно; план показывает прежнюю раскладку с меткой «закреплено (ожидает пересчёт)» на A; после POST /recompute план собирается заново с применением пина

#### Scenario: Конфликт pin и зависимости

- **GIVEN** задача B закреплена (спринт 2), но её блокирующая задача после пересчёта завершается в спринте 2
- **WHEN** пересчёт выполнен
- **THEN** конфликт помечен предупреждением (dependency_shift с задачей B и пояснением), человеку предложены варианты (снять pin / передвинуть pin позже); закреплённая позиция не изменяется автоматически, пока человек не выберет вариант

#### Scenario: Pin не влезает

- **GIVEN** закреплённое назначение превышает свободные часы инженера в закреплённом спринте (изменились данные)
- **WHEN** пересчёт
- **THEN** закреплённая позиция сохранена (pre-occupancy; аёты не нарушаются), соседние незакреплённые задачи этой роли отодвигаются; предупреждение указывает на закреплённый элемент

#### Scenario: Пересчёт игнорирует снятый pin

- **GIVEN** pin снят (DELETE /pin)
- **WHEN** пересчёт
- **THEN** задача расставляется планировщиком на общих основаниях (без pre-occupancy)
