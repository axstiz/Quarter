# Change: 017 — вид «Роли по спринтам»

## Why

В разделённой работе над планом уже есть view по задачам (Гант) и по загрузке (таблицы), но ресурсный вопрос «какая роль на каком спринте перегружена / не закрыта» словами не объясняется и в существующих видах виден плохо. Реализация (frontend) уже влита в develop — поведение сервиса есть, а спекой не зафиксировано; правим это.

## What Changes

- Новый режим отображения плана «Роли по спринтам» (вкладка `/plan?view=roles`; главный экран — Гант по решению лида после влития feature/frontend): матрица (команда × роль) × 6 спринтов.
- Для каждой роли: носители (инженеры со ставками, раскрываются), агрегатный лимит Σ (80 ч × capacity_rate носителей), загруженные часы роли в спринте (метр), чипы задач с часами роли.
- Кросс-командный заём: если носителей роли нет в команде задачи, часы уходят команде с наибольшим свободным лимитом (пунктирный чип с пометкой «из команды X»).
- Роль без носителей во всей компании — красная метка «виртуальный держатель» в команде задачи (согласуется со spec planning, change 003).
- Редактор раскладки живёт здесь: перетаскивание чипа двигает **часть задачи целиком** (SP/часы/все роли части вместе) между спринтами; недопустимые цели (спринт закрыт фактом, вне квартала, дубль другой части той же задачи) отклоняются с текстом причины; кнопка «Сбросить переносы». Ручные переносы — локальные (mock-бэкенд), не меняют расчёт бэкенда.
- Гант по задачам становится read-only по раскладке (причины, карточки, порядок задач в спринт-панели остаются); раскладка синхронна между видами (общее хранилище placement).
- Убирает прежний per-person разрез «По людям»: назначения людей сервис не хранит, вид оперирует агрегатами ролей (решение лида).

### New Capabilities

(нет)

### Modified Capabilities

- `ui`: добавляются требования «Вид „Роли по спринтам"» (матрица роли × спринты с носителями, лимитами, заёмами и виртуальными держателями) и «Единый редактор раскладки» (правка переносов только в виж roles, Гант read-only, синхронная раскладка, дефолтная вкладка).

## Impact

- Фронтенд: `frontend/src/features/plan/RolesView.tsx`, `frontend/src/lib/roleModel.ts`, `frontend/src/lib/ganttOverrides.ts`, `frontend/src/features/plan/GanttView.tsx`, вкладки `PlanPage.tsx`.
- Бэкенд и API не меняются — все агрегаты вычисляются фронтендом из существующих данных плана и инженеров.
- Относится к spec-only условию: спека фиксирует уже влитое поведение, чтобы договорённости лида были контрактом, а не устной практикой.
