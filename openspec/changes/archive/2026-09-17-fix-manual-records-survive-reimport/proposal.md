# Change: fix-manual-records-survive-reimport

## Why

Спека data («Ручные записи не затираются») требует: последующие импорты не перезатирают записи с source=manual — но `reset_dataset_tables` удаляет все строки импортных таблиц, включая созданные вручную через CRUD. Пользователь, исправивший задачу/инженера руками и перегрузивший датасет, теряет правки. Контракт `docs/api-contract.md` обещает обратное.

## What changes

1. `reset_dataset_tables` удаляет только строки `source != 'manual'` (импортные) в каждой из 5 таблиц; ручные правки переживают импорт.
2. Импорт пропускает задачу, чей task_id занят ручной записью (PK-конфликт) — ручная версия приоритетна.
3. Тест: ручной инженер/задача через CRUD → повторный /data/import → записи на месте.

## Non-goals

- Дельта спеки не нужна: capability data уже фиксирует требование (skip_specs).
- Наполнение справочников (change 011) — здесь только координация: будущий импорт справочников пойдёт по тому же правилу (не трогает manual).

## Risks

- Импортные записи не обновляются по-строчно, а пересоздаются: некритично (содержимое идентично датасету), но суррогатные id меняются при каждом импорте — контентных последствий нет.
