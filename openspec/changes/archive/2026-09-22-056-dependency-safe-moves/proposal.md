# Proposal: 056-dependency-safe-moves

## Why

Оптимизация падала с 422 «зависимость SRV-4011 → SRV-4012: зависимая стартует в спринт 3, блокер заканчивает в 3»: жадные сдвиги ступени 2 (`allocate_engineers`) не проверяют зависимости, `repair_dependencies` отрабатывал только ДО распределения, а любое нарушение черновика завершало job ошибкой. Плюс UI позволял перетаскивать задачи в спринты, нарушающие зависимости (проверки pin смотрели только на закреплённые задачи, не на фактические позиции).

## What Changes

- Optimize отрабатывает всегда: `repair_dependencies` после `allocate_engineers` (каскадный сдвиг зависимых за блокер, assignments синхронизируются; за спринт 6 → «выполнится частично»); остаточные нарушения черновика (пред- и пост-валидация) — не 422, а деградация в эвристику с честным `degradation_reason` в отчёте
- `pin_task`: зависимости проверяются против фактических позиций плана — блокер должен заканчиваться раньше целевого спринта, зависимая начинаться позже; нарушение → 409 с причиной
- UI (RolesView): жёсткий запрет drag в нарушающий зависимости спринт, причина в сообщении («зависит от X, которая заканчивается в спринте N»)
- QA live: pin зависимой в спринт блокера → 409; optimize → ready

## Capabilities

### Modified Capabilities

- `replanning` — безопасные переносы с учётом зависимостей; optimize без отказов по валидации черновика.
