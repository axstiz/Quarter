# Change: 019-data-table-editor (spec-only)

## Why

Спека onboarding требует «полный CRUD с опциональными полями» и «добор форм» для дозаполнения, но на фронте ручного редактирования загруженных данных нет — править или дополнять данные можно только повторной загрузкой файла. Решение лида (2026-09-18): дать пользователю (лиду, ресурсному менеджеру) открыто редактируемую таблицу загруженных данных — открыть, поменять, дополнить руками; это же закрывает раздел «дозаполнение недостающего» и усиливает критерий «удобство работы с планом» (10 баллов ТЗ). CRUD-ручки на бэке уже есть (POST/PUT/DELETE по tasks, engineers, teams, dependencies) — change фиксирует поведение редактора поверх них.

## What Changes

1. **ui** (ADDED):
   - страница «Данные» — редактируемые субтаблицы: Задачи, Люди, Команды, Зависимости (4 таблицы по решению лида);
   - правка ячейки in-place, добавление и удаление строк; часы по ролям задачи редактируются detail-видом внутри строки задачи;
   - inline-валидация при вводе и понятные ошибки бэка (422/409) прямо в ячейке/строке;
   - права: reader — просмотр; editor/admin — правки, добавление, удаление.
2. **onboarding** (ADDED):
   - контракт редактируемой таблицы: типизированные сообутности, а не свободные строки; инварианты при правках;
   - правки вручную переводят запись в source=manual и не затираются повторными импортами (состыковка с capability data);
   - данные «живые» для планирования: правки доступны planner'у при новой генерации; существующие версии планов не переписываются — после правки пользователю показывается баннер «данные изменились — постройте план заново» с кнопкой (human-in-loop, решение лида);
   - висячие зависимости и роли без носителей — редактируемы, но помечаются как риски планирования (согласовано с README «Обработка сервисом»).

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `ui`: требование «Редактор данных таблицей» (новый экран, in-place правки, права, inline-валидация, связь с планом через баннер).
- `onboarding`: требования «Правки данных вручную» (source=manual, дозаполнение недостающего), «Валидация правок» (инварианты и осмысленные ошибки), «Неинвалидация планов» (баннер + ручная пересборка).

## Non-goals

- Реализации в этом change нет (spec-only).
- Bulk-paste/импорт из буфера обмена, undo-history на уровне редактора (возврат прошлой версии данных возможен повторной загрузкой файла — остаётся прежним сценарием).
- Переписывание history планов при правках данных (версии неизменяемы, change 009).
- Мультиредактирование ячеек мышью с shift-выделением и формулы — не таблица Excel, а редактор записей.

## Risks

- Свободное редактирование Key-полей (task_id, engineer_id) может сломать ссылки зависимостей: правка ключей → бэк отклоняет, если ключ используется в зависимостях/плане (409 c подсказкой: сначала удалить зависимости).
- Конфликт одновременных правок (второй пользователь правит ту же запись): обработка как в 005 — версионность против last-write-wins findAll per entity; при конфликте 409 с данными другой стороны.
