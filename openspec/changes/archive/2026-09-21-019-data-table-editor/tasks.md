# Tasks: 019-data-table-editor

Реализация отдельным change по этому чеклисту. CRUD-ручки на бэке уже есть — основной объём в	ui и интеграции.

## 1. Страница «Данные» — каркас

- [x] 1.1 Маршрут `/data` с вкладками субтаблиц (Задачи / Люди / Команды / Зависимости); таблицы переиспользуют компоненты таблиц проекта; данные из существующих GET-ручок. Проверка: `npm run build`, все 4 субтаблицы открываются, данные совпадают с API
- [x] 1.2 In-place правка ячейки → PUT соответствующей записи; добавление/удаление строки — POST/DELETE; правка применяется после подтверждения пользователем (toast об ошибке). Проверка: правка поля задачи меняет данные бэка (и мока)
- [x] 1.3 Права: reader — заблокированные поля/кнопки (display-only); editor/admin — полный CRUD. Проверка: вход через демо-роли показывает/скрывает, на бэке 403 подтверждается

## 2. Валидация и детали

- [x] 2.1 Inline-валидация: числовые поля ≥ 0, capacity_rate ∈ {0.5, 1.0}, ссылочные поля на существующие записи; ошибки у ячейки, введённое значение сохраняется до исправления. Проверка: сценарий «−5 в часах» отклоняется с текстом у ячейки
- [x] 2.2 Detail-вид часов по ролям в строке задачи (add/edit/remove роль→часы, нулевые строки отбрасываются; роли без носителей помечены). Проверка: изменение role_hours доступно planner'у следующей генерации
- [x] 2.3 Висячие зависимости: строка помечена «планировщик проигнорирует»; маркер живёт при созданії и фиктивных данных. Проверка: создание зависимости на несуществующий id сохраняется с пометкой
- [x] 2.4 Правки переводят запись в source=manual; повторный POST /data/import не затирает ручные записи. Проверка: тест бэка повторного импорта вручную отредактированной записи

## 3. Связь с планом и навигация

- [x] 3.1 Баннер «данные изменились — постройте план заново» на страницах плана после правок (сравнение отметки времени данных с созданием активной версии); кнопка открывает построение. Проверка: сценарий руками: правка → план → баннер → пересборка → новая версия
- [x] 3.2 Переходы «редактировать данные» из карточки задачи и профиля инженера → строка в таблице Данных. Проверка: переход с подсветкой записи
- [x] 3.3 Бэк-зaщита ключей: PUT task_id/engineer_id при наличии ссылок (зависимости/план) → 409 с подсказкой. Проверка: API-тест 409
