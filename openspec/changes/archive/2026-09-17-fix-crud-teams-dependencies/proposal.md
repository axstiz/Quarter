# Change: fix-crud-teams-dependencies

## Why

Спека api требует «CRUD по сущностям: /teams, /engineers, /tasks, /dependencies (POST/PUT/DELETE)» — реализация не полная: у **teams** нет PUT (переименование), у **dependencies** нет PUT и DELETE. Фронтендер со стр. 0.1 не может переименовать команду и отредактировать/удалить зависимость — ручной ввод наполовину недоступен. Попутно: сценарий в спеке planning назван «План из 48 задач», а задач в датасете 45 (текст сценария корректен, опечатка в имени).

Решение лида: изменения зависимостей идентифицируются **по паре** (blocking/blocked task_id), а не по суррогатному uid (пары показывает фронтенду, uid — нет).

## What changes

1. Код `src/api/crud.py`:
   - `PUT /api/v1/teams/{team_id}` (тело `{name}`) — переименование; правка делает запись ручной (source=manual — переживает импорт, как у задач)
   - `PUT /api/v1/dependencies?blocking_task_id=X&blocked_task_id=Y` (тело `{dependency_type}`) — смена типа; запись → source=manual (выживает повторный импорт)
   - `DELETE /api/v1/dependencies?blocking_task_id=X&blocked_task_id=Y` — удаление по паре; 404, если пары нет
2. Опечатка сценария «План из 48 задач» (в датасете 45): исправляется позже отдельным spec-only изменением — валидатор требует прежнего имени сценария в MODIFIED-дельте, переименование не разрешено without полной copy. Отложено.
3. Тесты: переименование команды, смена типа/удаление зависимости по паре, 404 несуществующих.

## Non-goals

- Отдельная DELETE с uid-параметром — по решению лида идентификация по паре.
- Восстановление импортных зависимостей после PUT(сделает запись manual) — семантика «правка = вручную» из capability data работает как есть.

## Risks

- PUT по паре без uid: неоднозначность при дублях пары — импорт дедуплицирует пары (см. importer), так что пары уникальны; тест это фиксирует.
