# Design: 021-workspaces-ui

## Контекст

Спека-only для фронтендера; бэк 008/009 влит: `/workspaces` (GET/POST), `/workspaces/{id}` (PUT/DELETE), `/workspaces/{id}/members` (GET/POST/DELETE), `/permissions/matrix` (GET), `/permissions/roles/{role}` (PATCH), `/permissions/audit` (GET). В мок-бэкенде workspace-ручек нет — их добавляют в мок (внешняя задача к change 021, важно для dev-сценария без бэка).

## Решения

1. **Контекст в обвязке клиента** (как жд mod auth-сессии): активный workspace хранится в localStorage (`quarter-auth` или рядом); `client.ts` пристраивает `X-Workspace-Id` на все `/api/v1`-запросы, если выбранное ≠ default. Единое место — не каждая ручка фронта. Смена workspace — действие обвязки: обновить localStorage + сбросить URL-state контента — код фронта получает только актуальные данные.
2. **Onboarding-экран после входа — всегда**: предсказуемость демо-сценария; при единственном (default) — шаг через экран затратен в одном клике, но избавляет от «скрытого» контекста (важно для reviewers, проверяющих переходы). «Чистый лист» нового workspace — переиспpool всего загрузочного флоу `/import` (файл/демо-датасет кнопкой — из влитой feature/frontend), а неновый pipeline.
3. **Роли-гейтинги повторного грана**: reader — список workspace read-only, без форм; editor — действия в контексте; admin — участники/матрица/аудит. Роли вычисляются бэком по membership в выбранном контексте (токен не гоняется по роли доверия: сервер возвращается роль в контексте — фронт берёт её из ответов (например, GET /auth/me в контексте workspace).
4. **Матрица 009**: перед amerikanец правки, которая могла бы заблокировать admin-механики, UI требует подтверждения (инвариант уже на бэке — UI лишь объясняет).
5. **URL-state reset**: `?plan=/task=` удалseller при смене workspace, чтобы приглашённая ссылка не выдавала плана чужого контекста.

## Муки

- Имитация 008/009: `/workspaces` GET/POST, members CRUD (по email), `/permissions/matrix`, `PATCH /permissions/roles/{role}`, `/permissions/audit` + 404/403 семантика не-участника. Сверка звучит мока ↔ бэка по сценарию «38 запросов + workspace-сцена».
- Языки старта «чистого листа»: новый workspace в моке — пустые списки; кнопка демо-датасета ведёт в импорт-flow (/data/import набора).

## Риски

- Несоответствие хранения active workspace между вкладками (двух вкладок с разными workspace) — взаимодействие через событие storage (обновление контекста при параллельной загрузке); справедливая задача фронтендера — вести себя неконфликтно.
- Onboarding-экран и `X-Workspace-Id` выполняются в одном change — перед него отсутствие заголовка на не-default остаётся угрозой; согласовано ведение одного прохода.
