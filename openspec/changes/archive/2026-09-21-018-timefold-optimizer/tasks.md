## 1. Сайдкар optimizer

- [x] 1.1 Скелет сервиса (Java/Kotlin, Timefold Solver): доменная модель assignment (часть задачи × спринт × команда × роль) + staffing-перемещения; Dockerfile; docker-compose профиль `optimizer` с внутренним портом. Проверка: `docker compose --profile optimizer up` поднимает сервис, health-эндпоинт отвечает
- [x] 1.2 Ограничения (hard): ёмкость velocity × 0,8; 80/40 ч по ставкам; role_hours по частям; зависимости; Done/InProgress остатки; виртуальные держатели; запрет переноса единственных носителей компетенций. Проверка: юнит-тесты Timefold Score на синтетических доменах (блокировка из-за зависимости, перегруз роли, единственный носитель)
- [x] 1.3 Целевая функция: инициативы → SP заказчика → PI-норма; штрафы: незакрытые человеко-часы, переносы людей, порядок priority. Проверка: score-тест показывает предпочтение задач заказчика и штраф переноса
- [x] 1.4 HTTP solve-контракт (снапшот → черновик + score), seed/лимиты времени/порог переноса из конфига; детерминизм при фиксированном seed. Проверка: два прогона с одним seed дают идентичный черновик
