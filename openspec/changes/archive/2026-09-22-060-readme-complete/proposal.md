# Proposal: 060-readme-complete

## Why

README (после переработки фронтендером) — лицо сдачи (критерий «Воспроизводимость и качество README», вес 10), но не содержал: подробный запуск с нуля, схему папок, актуальные методики (изменились в changes 045–059), единый раздел допущений (требование ТЗ: «допущения при обработке пропусков», «правила приоритизации, переноса и отмены», «если алгоритм связывает SP и часы — опишите способ и допущения») и явную сверку с критериями ТЗ/онбординга.

## What Changes

- README: «Запуск с нуля в Docker» — требования, .env, сборка, таблица сервисов с проверками, VPN-заметка про host-сеть, импорт данных, демо-сценарий по шагам, управление/сброс, траблшутинг
- README: «Структура репозитория» — дерево папок с описанием
- README: «Методологии расчёта» обновлены — базовые ограничения (ТЗ/онбординг), жадный планировщик (одна донорская + запасная + отложка, минимум части 2 ч, исполнитель vs владелец), оптимизация полным циклом (pre-split, solver hard/soft, repair после ступени 2, горизонт после фактов, деградация в эвристику), пины с проверками, метрики/Bus Factor/советник с наймом по дефициту ролей
- README: «Допущения» — назначение по роли (skills справочно), InProgress без spent_time = полная оценка, SP↔часы не связываются (обоснование), заём/виртуальные держатели обязательны (дефицит заложен в датасет), висячие зависимости, даты, витринные факт-часы, факт спринта, AI-советник, ограничения реализации
- README: «Соответствие ТЗ» — таблица критериев жюри и пунктов онбординга → где в сервисе
