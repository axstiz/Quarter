# Design: 020-frontend-boundary

## Контекст

Правило лида «данные — фронт, действия — бэк» Закрепляется spec-only: код выполняется отдельным change. Важно, что **обе бэк-ручки уже влиты** — перенос не требует новых эндпоинтов, только перестройки фронта:

- pin/unpin — `POST/DELETE /plans/{id}/tasks/{task_id}/pin` (change 016, require_permission `plans_generate`);
- bus-risk — `GET /plans/{id}/bus-risk` (изменён в change 003 API, расширен 014 scopes).

## Решения

1. **Перенос = немедленный пин** (решение лида): честная семантика pin — «задача закреплена за этим спринтом». Drag — не «что-если», а операция; откат через «снять закрепление» (DELETE pin) и историю версий. Попутно это устраняет UX-раскус «вручную распределять нельзя на живом бэке» (изменит mock-only ограничение прошлого слоя).
2. **Валидация целей на клиенте до пина** (фикс-спринт/вне квартала/duplicate) остаётся — экономит раунды и не заставляет бэк повторять презентационные проверки; настоящие business-правила (ёмкость 409) остаются серверными.
3. **Bus-risk view** переключается на ручку без пересчёта: в PlanPage стат и RiskPanel источник — response ручки; клиент ловит её ошибку как явную (не вырождать в 0).
4. **Витринность сохраняется** (решение лида): ролевой-вид и LoadView продолжат считать проекции на клиенте — это безопасно, потому что данные одна-две.normalized и подписи обязательны (текущее требование 017 «вид „Роли по спринтам"» записывает подпись). Приложения UI-строки обновляются к единому виду модификаторомcalculations.

## Что меняется в фронте (объём для фронтендера)

- `src/lib/ganttOverrides.ts` (placement/localStorage) — удаляется; drag в `RolesView` пишет главы через `api.pin/unpin` (`endpoints.ts` +2 ручки), «Вернуть/Сбросить» → unpin;
- `src/features/plan/busRisk.ts` — удалён; потребители (PlanPage stats, RiskPanel) — на ручке;
- `queries.ts` — `useBusRisk` (endpoint keys), invalidation при пересчёте;
- моки: `handleMock` pin/unpin уже поддерживаются (016); добавить mock answer для `/plans/{id}/bus-risk` (было выведено из /bus-factor — теперь ответ ручки);
- подписи витринных расчётов — сохраняются без изменений.

## Риски

- Pin-механика «честная» (меняет план при пересчёте): тесты и сверка мока ↔ бэка должны проверять: drag → pin POST → план пересчитан → часть в новом спринте; конфликтный pin → 409 текст.
- Task order (локальный контроль сил от pp) внутри очереди остаётся витриной — не конфликтует с пином (pin фиксирует спринт/носителя, не порядок до следующего пересчёта).
