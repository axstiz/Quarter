# Change: 020-frontend-boundary (spec-only)

## Why

Решение лида (2026-09-21): **данные рисует фронт, любые бизнес-действия и перестановки идут через бэкенд и БД**. Сейчас два места это правило нарушают: (1) ручные переносы раскладки хранятся в localStorage и работают только в мок-режиме (на живом бэке drag выключен — действие не сохраняется вообще); (2) bus-риски («N задач под угрозой») фронт вычисляет сам, склеивая `/bus-factor` × `role_hours`, хотя ручка `GET /plans/{id}/bus-risk` уже реализована — это дублирование бэк-логики с уже случившимся рассинхроном (фронт не учитывает scopes 014).

## What Changes

1. **ui** (MODIFIED):
   - **Единый редактор раскладки** — перенос чипа роли сохраняется немедленным бэк-пином: drag → `POST /plans/{id}/tasks/{task_id}/pin {sprint_no, engineer_id?}` (ручки 016 влиты, require_permission); конфликт ёмкости (409) показывается пользователю текстом причины; «вернуть» — `DELETE pin`. Локальный слой переноса (localStorage по planId) устраняется — переносы работают на реальном бэке и попадают в данные плана/историю версий.
   - **Bus-риски** — виджет дашборда и панель рисков читают данные из `GET /plans/{id}/bus-risk`; фронт-расчёт (склейка /bus-factor с role_hours) удаляется (of коробки compatibility с bus-factor.requirement «Риски плана в терминах задач»).
2. **ui** (ADDED): требование «Граница вычислений» — правило разделения труда: показ данных (витринные проекции: «Роли по спринтам», LoadView, группировки инициатив, URL-состояние) — ответственность фронтенда (с обязательной подписью), любая операция, меняющая данные (переносы, cancel, priority, факт, recompute, генерация) — только бэкенд-ручки; клиентские in-memory слои для persist-действий запрещены.
3. Совместимость: все существующие требования витринности («Вид „Роли по спринтам"» → подпись «распределение вычисляет клиент») сохраняются; бэк-ручки для пина/recompute уже в архитектуре 008/009/016.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `ui`: «Единый редактор раскладки» — перенос через бэк-пины (немедленный POST, «вернуть» — DELETE, без localStorage); «Bus-риски» — источник ручка /plans/{id}/bus-risk; ADDED «Граница вычислений» (данные — фронт, действия — бэк).

## Non-goals

- Реализации в этом change нет (spec-only) — код отдельным change по tasks.md (исполнитель — фронтендер).
- Переписывание «Роли по спринтам» под данные `assignments` (агрегация для отображения остаётся клиентской — витрина, требование 017 подписи сохраняется).
- Новых бэк-эндпоинтов нет: пины и bus-risk ручки уже влиты (016, 003/014).

## Risks

- Изменение семантики drag: «перетащенный чип» теперь значит «закрепить в БД» (pin); mitigation — тост с результатом и кнопкой «снять закрепление», история версий позволяет откат.
- Пин на «что-если» без пересчёта не пересобирает план мгновенно — раскладка видна после пересчёта; спека указывает, что UI прерывает обмен (поясняет, когда план обновится).
- Мок-режим должен имитировать ручки пина так же, как живой бэк, иначе сверка мока и бэка (38 запросов, README фронта) распадётся — во включены в tasks.
