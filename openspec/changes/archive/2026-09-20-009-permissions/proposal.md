# Change: 009-permissions (spec-only)

## Why

Решение лида: права доступа выделяются в отдельную систему с настройкой админом, а не «зашиты» в код по ролям. Связка: capability auth (вход/сессии) + capability workspace (компании) + настоящая capability — матрица «роль → ручка/действие», которую админ workspace-а настраивает (включая включение/отключение отдельных возможностей для роли).

## What changes

Новая capability `permissions`: матрица прав действия → роли (admin/editor/reader) на уровне workspace; админская настройка прав (выдача/съём отдельных прав и ролей участникам); журнал (кто выдал/сменил права); проверка прав при каждом изменяющем действии вплоть до 403 с объяснением; предустановленная матрица по умолчанию (admin — всё, editor — правки, reader — чтение).

## Non-goals

- Поштучные ACL на каждую задачу/план (доступ — на уровне workspace и действия; не до записи).
- Рабочее самоназначение ролей пользователем — запрещено (capability auth).
- Реализации в этом change нет (spec-only).

## Risks

- Зависит от capabilities auth (сессии) и workspace (контекст): реализуется после 005/008.
- Рост сложности матрицы: держим перечень прав ограниченным (права — на действия, не на поля данных).
