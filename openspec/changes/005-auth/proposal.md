# Change: 005-auth (spec-only)

## Why

До демо-прототипа сервис открыт (все ручки без аутентификации) — это осознанное упрощение для проверки пользовательского сценария. К подключению команды и публичному демо-серверу нужна многопользовательность: у каждого лида свои планы/правки, роли определяют права. Спека фиксирует контракт заранее (spec-only, без кода) — реализация отдельным change по tasks.md.

## What changes

Новая capability `auth`: роли admin/editor/reader, локальные по workspace-у; доступ раздаёт админ workspace-а (владелец проекта), не саморегистрация — закрытый режим с приглашениями/одобрением; регистрация/вход (email+пароль); демо-пользователь для проверки; закрытие ручек без сессии (кроме healthz/docs); немедленное следствие — CORS_ORIGINS перестаёт быть `*`; конкурентные правки плана решаются через существующую снапшот-цепочку (не last-write-wins).

## Non-goals

- OAuth/SSO/2FA, восстановление пароля, mail-подтверждения — минимум для демо.
- Реализации в этом change нет.
- Несколько компаний в одной инсталляции (мультитенантность) — отдельная spec-only change `008-workspaces` (создаётся параллельно), чтобы auth оставался минимальным.
- Полная изоляция данных по пользователям — НЕ цель: демо использует общий датасет; auth защищает записи от чужих правок, а не от просмотра (баланс уточняется при реализации).

## Risks

- Добавление auth затрагивает все ручки: e2e-тесты перейдут на аутентифицированные запросы — потребуется фикстура в tests/ (учтено в tasks).
