# Change: 008-workspaces (spec-only)

## Why

Сейчас вся инсталляция — рамки одной компании: 1 датасет (xlsx) → БД → планы/карта. Решение лида: пользователь (консультант/ресурс-менеджер) может вести несколько компаний — каждая со своим датасетом, людьми, задачами, планами и настройками, с переключением между ними. Это мультитенантность внутри одного сервиса: решение лида: доступ и данные по компаниям разделяются, владелец компании управляет доступом в своей компании (роли и права внутри компании — см. capability auth).

## What changes

Новая capability `workspace`: несколько компаний (workspace-ов) в одной инсталляции; каждая сущность (задачи, инженеры, зависимости, история, планы, job-ы онбординга) принадлежит своему workspace; контекст работы выбирается пользователем (переключение/заголовок), доступ к чужому workspace — 403/404; владелец workspace управляет составом и ролями его участников (соединяется с capability auth); демо-датасет и существующие данные переезжают в дефолтный workspace (обратная совместимость: одно-датасетное поведение сохраняется).

## Non-goals

- Отдельные БД/кластеры на компанию (database-per-tenant) — изоляция логическая, в одной БД.
- Реализации в этом change нет (spec-only).
- Шеринг данных между компаниями (общие задачи/люди) — вне рамок: компания замкнет свои данные.

## Risks

- Затрагивает все таблицы и ручки — большие миграции; совместимость «одного workspace» должна быть обеспечена тестами без заголовка workspace.
- Импорт (data/import) в текущем виде затирает общие таблицы (reset_dataset_tables) — потребует при реализации переделать в по-workspace импорт.
