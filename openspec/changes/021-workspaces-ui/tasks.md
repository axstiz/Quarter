- [ ] 1.1 Активный workspace в клиентской сессии (localStorage рядом с auth-токеном); `client.ts` шлёт `X-Workspace-Id` на все `/api/v1`-запросы, когда контекст ≠ default. Проверка: запросы при переключении несут корректный заголовок, default — без异
- [ ] 1.2 Смена workspace — через обвязку: обновление контекста + сброс URL-state (`?plan=`, `?task=`). Проверка:場合は ссылки со старым ?plan= не переводят в планы чужого контекста

## 2. Онбординг-экран и «чистый лист»

- [ ] 2.1 Экран «Выбор рабочего пространства» — первый экран после успешного входа, Всегда: список (название, роль, владелец), «Создать рабочее пространство». Проверка: вход → список, не /plan напрямую
- [ ] 2.2 Создание workspace (POST /workspaces) — создатель становится админом, автоматом открыт «чистый лист» (пустые данные) с двумя действиями: загрузить файл или **демо-датасет одной кнопкой** (переиспользование влитой кнопки демо-импорта). Проверка: создание → пустой контекст → демо-кнопка наполняет данные
- [ ] 2.3 Возврат на экран выбора: селектор в топбаре/сайдбаре «сменить компанию»; активный помечен. Проверка: переключение в обе стороны, состояние сброшенного контента чистое
