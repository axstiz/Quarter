# Proposal: 039-pin-apply-now

## Why

Перемещённый чип не отражается в БД — при пересчёте могли появиться «фантомы» (позиция задачи расходится с намерением юзера). Nайдens live QA: каждый перенос должен сразу отражаться однозначно (из старой колонки исчезло, в целевую попало, БД фиксирует немедленно) — без пересборки остального плана (change 032).

## What Changes

- `POST .../pin`: немедленное перемещение данных задачи в БД: строки PlanItem (sprint_no=целевой) + assignments (перенесённые часы/роль/инженерricks с новым sprint_no); pinned_sprint = целевой. Без generate_plan; остальной план не трогает
- Лёгкая проверка ёмкости при пине: если суммарные плановые часы инженера в целевом спринте + часы задачи > лимит (80×ставка) → 409 с текстом причины
- Optimistic UI (038) становится консидентным: сервер встаёт в ту же раскладку немедленно
- Spec-delta planning MODIFIED: пин применяется немедленно к данным задаче (перемещение есть фиксация данных без пересборки соседей), конFLICT ёмкости 409 на pin

## Capabilities

### Modified Capabilities

- `planning` — «Закреплённые назначения (pin) — жёсткие якоря»: немедленное перемещение теперь «жёстко якорное» (данные задачи и assignments обновляются в БД сразу, соседи не трогаются, remain позиция до пересчёта).

## Impact
`src/api/routes.py` (pin), specs planning.
