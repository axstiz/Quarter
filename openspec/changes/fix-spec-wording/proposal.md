# Change: fix-spec-wording

## Why

Две косметические неточности в main-спеках, накопившиеся из ранних итераций:

1. **planning**: сценарий назван «План из 48 задач», а в датасете 45 задач (текст сценария верен, число в имени — пережиток старой итерации). Прямое переименование сценария валидатором не разрешено внутри MODIFIED (требуется сохранение прежнего имени); механика REMOVED+ADDED одного требования также запрещена — правка невозможна чистым change'ом.
2. **api**: в перечне ручек онбординга написано «POST /ai/normalize» — фактически ручка адресует конкретный job: `POST /ai/normalize/{job_id}` (в код и в `docs/api-contract.md` так и указано).

## What changes

1. **api**: MODIFIED «Ручки онбординга» исправляет `POST /ai/normalize` → `POST /ai/normalize/{job_id}` (сценарий «CRUD человека» сохранён полностью).
2. Опечатка сценария «План из 48 задач» (в датасете 45): НЕ исправляется механикой OpenSpec — переименование сценария не поддержано (REMOVED+ADDED одного требования запрещено, RENAMED только для requirement-ов). Принимается как известная неточность имени сценария; текст сценария корректен.

## Non-goals

- Никакого кода: изменения формулировок, поведение не трогается (поведение уже соответствует).
- Прочие правки спек — не в этот change, чтобы он оставался точно-минимым.

## Risks

- REMOVED+ADDED одного требования запрещено валидатором («Requirement present in both ADDED and REMOVED»); RENAMED поддержан только для requirement-ов, не сценариев. Итог: опечатка остаётся известной неточностью заголовка сценария.
