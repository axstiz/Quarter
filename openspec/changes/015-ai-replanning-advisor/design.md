## Context

Пересчёт плана — детерминированная математика (SP-гейты, часы ролей, зависимости — PDF-инварианты, спека planning/replanning). Оптимизационные варианты посчитаемы ядром (стратегия 013, optimization-report, staffing-suggestions). Недостающий слой — интерпретация: «что это значит для менеджера, что двигать, какую инициативу спасать». Устная фраза лида: «пересчёт — не агенту; агент советует». В репо уже есть AI-слой (LangGraph, GigaChat, деградация без ключа — change 002) — советник добавляется тем же паттерном.

## Goals / Non-Goals

**Goals:**
- Ручка-советник: детерминированная сводка → агент → структурированные советы (pydantic), human-in-loop
- Деградация без GigaChat: те же советы собраны из отчётов ядра (работа без LLM)
- Чистая архитектура: planner/services не зависят от агента

**Non-Goals:**
- Автоприменение советов; новые мутационные ручки
- Делегирование агенту пересчёта/гейтов/зависимостей
- LLM-оптимизатор вариантов (перебор — детерминированным ядром, не моделью)

## Decisions

- **Разделение вычислять vs советовать**: числа (SP, часы, KPI, дефициты) всегда от ядра; агент только интерпретирует и ранжирует готовые опции (опции уже посчитаны в optimization-report и staffing-suggestions). Это снимает риски hallucination чисел и обеспечивает воспроизводимость пересчёта судьями
- **Советники по состоянию, не по сессии**: вход — facts-JSON версии плана (компактная проекция: риски+KPI+отчёты, ~десятки строк), выход — список advisory. Промежуточные шаги графа: enrich (дополнить справочным контекстом: нормы KPI, правила перепланирования) → draft (LLM) → validate (pydantic) → fallback (детерминированные подсказки)
- **Единая деградация через общий код-путь**: fallback — те же структуры `{kind, ...}, numeric_basis`, построенные из отчётов; демо без ключа выглядит как полноценный советник
- **Потребители советов**: дашборд (кнопка «Советы»), экран спринта (стр. 2, блок рисков) — UI-интеграция описывается дельтой 006-ui при реализации этого change

## Risks / Trade-offs

- Совет противоречит данным (эффект неверно интерпретирован) — numeric_basis и expected_effect обязательны; тест сопоставляет причину совета с отчётом, на котором она построена
- Деградация самостоятельно уступает LLM-варианту — trade-off принят: стабильность и работа без сети важнее «красивых» советов на демо
