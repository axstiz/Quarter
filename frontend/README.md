# Frontend — квартальное планирование

React 19 + TypeScript + Vite, TanStack Query, React Router, Motion (анимации), Sonner (уведомления),
Radix Dialog (подтверждения), Lucide (иконки). Стили — обычный CSS на токенах (`src/styles`).

```bash
npm install
npm run dev     # http://localhost:5173, моки включены в .env.development
npm run build   # страницы грузятся лениво, моки в прод-бандл не попадают
```

Реальный бэкенд: `VITE_API_MOCKS=false`, Vite проксирует `/api` → `http://localhost:8000`.

## Дизайн-система

Опирается на гайды: [interface-design](https://github.com/Dammyjay93/interface-design) (иерархия, токены, плотность),
[emil-design-eng](https://github.com/emilkowalski/skills) (анимации), [ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) (приоритеты UX-правил).

- **Направление:** «инженерная ведомость» — графит на бумаге, один акцент `--plan`, плотность как у рабочих инструментов.
- **Токены** (`styles/tokens.css`): поверхности `paper/sheet/well`, текст `ink…ink-4`, статусы `done/shift/over/pending`; тёмная тема — подмена токенов (по системе + переключатель).
- **Шрифты:** Onest (кириллица) + JetBrains Mono для ключей задач; шкала 1.25 от 14px, `tabular-nums` для чисел.
- **Глубина:** тонкие границы; тень только у всплывающих слоёв (панель на узком экране, диалог, тосты).
- **Статусы** всегда текстом + цветом, не только цветом.

## Анимации

Правила: только `transform`/`opacity`, ease-out `cubic-bezier(0.23, 1, 0.32, 1)`, 120–260 мс, выход быстрее входа,
`prefers-reduced-motion` уважается (Motion `reducedMotion="user"` + CSS). Hover-эффекты — только для точного указателя.

| Действие пользователя | Анимация |
|---|---|
| Нажатие любой кнопки | `scale(0.97)` 120 мс |
| Смена раздела | проявление контента 200 мс |
| Смена вкладки | индикатор переезжает (layout) |
| Открытие задачи/человека | панель выезжает справа 260 мс, закрытие 180 мс; смена записи — кроссфейд с blur 2px |
| Раскрытие спринта | шеврон поворачивается, содержимое проявляется |
| Фильтры | новые строки проявляются; при запросе список приглушается |
| Приоритеты | перетаскивание и стрелки с анимацией перестановки; панель несохранённых изменений появляется |
| Пересчёт / загрузка факта | числа доезжают до новых значений, шкалы ёмкости перетекают, отчёт о рисках — каскадом 40 мс |
| Подтверждения | диалог: подложка + scale 0.97→1 |
| Импорт | шаги сменяются сдвигом по горизонтали |
| Тема | кроссфейд через View Transitions |
| Результаты действий | тосты Sonner (сверху по центру — не закрывают панели действий) |

## Экраны и откуда взят UX

| Путь | Что делает | Образец |
|---|---|---|
| `/plan` (вкладка по умолчанию, `?view=sprints`) | Диаграмма Ганта (спека ui): одна полоса на задачу от первого до последнего спринта, части — сегменты с долями SP, пропущенный спринт — пунктир, «выполнится частично» — открытый край полосы и остаток SP в колонке «Вне квартала»; там же перенесённые/отменённые с причиной. Строки — по инициативам (`?group=`: «X из Y в квартале») или по командам (SP / ёмкость). Панель задачи ложится поверх сетки | бэклог Jira, таймлайн Linear |
| `/plan?view=roles` | Роли по спринтам: строки (команда × роль), ячейки спринтов — чипы задач с часами роли; у роли раскрываются носители и агрегатный лимит (Σ 80 ч × ставка). Задача без носителя роли в команде уходит команде с наибольшим свободным лимитом (пунктирный чип, заём); роль без носителей в компании — красная метка «виртуальный держатель». **Редактор раскладки здесь**: перетаскивание чипа двигает часть задачи целиком (mock-бэкенд), раскладка синхронна с «Диаграммой Ганта» | планировщики ресурсов (Float, ClickUp Workload) |
| `/plan?task=ID` | Панель задачи справа: поля, почему такое решение, роли и носители, зависимости, отмена | issue view Jira |
| `/plan?view=load` | Команды × спринты (SP / ёмкость), роли × спринты (часы / доступно), перегруз текстом | планировщики ресурсов (Float, ClickUp Workload) |
| `/plan?view=priority` | Ранжированный список, перетаскивание и кнопки, одно действие «Сохранить и пересчитать» | ранжирование бэклога |
| `/sprint` | Отметить выполненное → сводка «что уйдёт дальше» → подтверждение → риски и сдвиги | закрытие спринта в Jira |
| `/team-map?view=people` | Фильтры слева + таблица людей, профиль справа | справочники сотрудников (Aboard, Dealfront) |
| `/team-map?view=teams` | Команды (FTE, ёмкость, velocity, общие люди) и матрица роли × команды | skills matrix |
| `/team-map?view=competencies` | Bus Factor по компетенциям с методикой и областью расчёта | — |
| `/metrics` | Выполнение квартала и таблица «запланировано / выполнено» по спринтам, история версий | sprint report Jira |
| `/login` | Вход: три демо-роли (reader/editor/admin) или email/пароль; токен в localStorage, `Authorization: Bearer` на все `/api/v1`-ручки, 401 → `/login?expired=1`; reader — только просмотр (кнопки правок отключены) | SSO/демо-входы |
| `/import` | Файл → сопоставление колонок и вопросы → проверка → импорт; для reader — заглушка «только просмотр» | CSV-импортеры |

Всё состояние экрана (вкладка, фильтры, выбранная задача/человек, версия плана `?plan=`) лежит в URL —
ссылкой можно поделиться, «Назад» работает.

## Моки

`src/mocks` — мок-бэкенд, который повторяет реальный, а не придумывает данные:

- **Данные** (`mocks/data/dataset.ts`) сняты с ответов бэка после `POST /data/import`: задачи, инженеры, зависимости, история команд, ответ `/data/upload` на xlsx-датасет. Приоритеты — по правилам импортёра.
- **Логика** (`mocks/engine.ts`) — построчный порт `src/services/planner.py`, `replanner.py`, `metrics.py`, `bus_factor.py`, `routes._recomputed_plan`. Задачи разбиваются между спринтами так же, как на бэке.
- **Ручки** (`mocks/index.ts`) — те же статусы, тексты ошибок, форматы (`created_at` без `T`), хранение строк плана как в `plan_items`.
- **Стартовое состояние** — как бэк после импорта: данные есть, планов нет. Состояние переживает перезагрузку (localStorage); сброс — открыть любую страницу с `?mock-reset`.

Сверка с реальным бэком (бэк на SQLite, без Docker): `POSTCODE_DATABASE_URL=sqlite+aiosqlite:///tmp/t.db uv run uvicorn src.main:app --port 8765`, затем один и тот же сценарий из 38 запросов гоняется по бэку и по моку и сравнивается по значениям. На момент сверки расхождения только там, где мок следует спеке, а бэк — нет (см. ниже).

### Расхождения бэка со спекой (мок следует спеке)

| # | Что на бэке | Что по спеке / в моке |
|---|---|---|
| 1 | `confirm-cancel` меняет только текст причины, `decision` остаётся `cancelled_pending` | задача становится `cancelled` |
| 2 | Метрики версии после факта не учитывают факт родителя: у пересчитанного плана все спринты «прогноз» | факты по всей цепочке версий |
| 3 | Пересчёт берёт факты только текущей версии: при втором факте задачи, закрытые первым, планируются заново; повтор факта того же спринта в дочерней версии не даёт 409 | факты и 409 по всей цепочке |
| 4 | `POST /data/jobs/{id}/confirm` после `/data/import` дублирует `task_role_requirements` и `team_history` (часы ролей удваиваются) | повторный импорт не должен дублировать |
| 5 | `recompute` по умолчанию `after_sprint=0` — перепланирует уже прошедшие спринты | фронт передаёт `after_sprint` = последний спринт с фактом |
| 6 | Предупреждения «дефицит роли» сравнивают роли с учётом регистра и только внутри команды (десятки сообщений, `доступно 0 ч`) | мок повторяет бэк; фронт группирует сообщения |

## Как убрать моки

1. `rm -rf src/mocks`
2. В `src/api/client.ts` удалить `USE_MOCKS` и блок `if (USE_MOCKS) { … }`
3. В `src/app/Layout.tsx` убрать ветку подписи «Мок-данные»
4. Удалить `VITE_API_MOCKS` из `.env.development` и `src/vite-env.d.ts`

## Особенности данных бэка, которые учитывает фронт (`lib/planModel.ts`)

- одна задача может стоять в нескольких спринтах («часть 1 из 2»), счётчики считают задачи, а не строки;
- выполненные по факту задачи приходят в `not_planned` с `sprint_no` — показываются в своих спринтах;
- в `sprints` приходят только спринты с запланированными задачами — фронт всегда рисует 6.

## Что считается на фронте (нет ручки)

- Задачи под угрозой Bus Factor: роли из `role_hours` × роли `scope=company, factor=1` (`features/plan/busRisk.ts`)
- Доступные часы роли: сумма `80 × ставка` по `/engineers`, сравнение названий ролей без учёта регистра
- Приоритеты: `PUT /tasks/{id}/priority` по одной задаче, затем `POST /plans/{id}/recompute`; текущий `priority` в плане не отдаётся — исходный порядок берётся из раскладки по спринтам
- warnings/diff запрашиваются у версии, в которую загружен факт (`parent_plan_id` текущего плана)
