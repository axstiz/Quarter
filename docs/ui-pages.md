# Постраничное описание интерфейса (для фронтендера и заказчика)

> Что видит и делает пользователь — без внутренней реализации. Источник истины по product-решениям: `docs/product-plan.md` (user flow v0.4.2) и спеки `openspec/` (changes 005–011). Контракт данных — `docs/api-contract.md`, `openapi.json`. Версия описания: 2026-09-17.
>
> Пометки статуса: **[есть в бэке]** — данные/ручки уже отдаются; **[change 00N]** — согласовано (spec-only), появится после реализации соответствующего change.

---

## Общие принципы (везде)

- **Контекст компании**: всё, что видит пользователь, принадлежит одной выбранной компании (workspace). Название текущей компании всегда в шапке, рядом — селектор быстрого переключения. Данные других компаний не видны нигде. [change 008]
- **Доступ по приглашению**: компанию видят только её создатель и приглашённые участники — чужая компания для пользователя просто не существует (не в списке, ручки её данных дают «не найдено/запрещено» без раскрытия содержимого). Просмотр и правки — одинаково закрыты для не-участников. [change 008]
- **Роль пользователя** определяет доступность кнопок внутри компании: **читатель** (reader) видит всё, но без кнопок изменений; **редактор** (editor) управляет планом и данными; **админ** (admin) — всё, включая управление участниками и правами. Роль локальна по компании (в A — редактор, в B — читатель — не связаны). Роли раздаёт админ компании, саморегистрация закрыта. [change 005/009]
- **Пометка «прогноз / факт»** везде подписана текстом — число без подписи не показывается.
- **Причины всегда объяснены**: любое решение системы (включила задачу / перенесла / отменила / выполнила) имеет видимую причину человеческим языком.
- Ошибки понятны: «сначала импортируйте данные», «факт этого спринта уже загружен», «действие недоступно вашей роли».
- Правка любых данных создаёт **версию** (правки разных людей не затирают друг друга), авторство правок видно. [change 005]

## Стр. 0 «Вход» [change 005]

- Форма входа: email + пароль. Регистрация — по приглашению от админа (закрытый режим); пароль хранится безопасно.
- Кнопка **«Войти как демо-пользователь»** — сессия без регистрации (роль на демо-компании), для проверки сервиса на демо-сервере и локально.
- После входа пользователь всегда попадает на «Мои компании».

---

## Стр. 0.2 «Мои компании» [change 008/009]

Первая страница после входа. Каждая компания — самостоятельный мир: свой датасет, люди, задачи, планы, участники.

**Что видит** — карточки **своих** компаний (и только их: создатель или приглашённый — чужие не видны вовсе):
- название + **моя роль** (админ / редактор / читатель; создатель = админ);
- наполненность: сколько задач/людей, есть ли план;
- отдельно — компания-по-умолчанию со встроенным демо-датасетом (совместимость и онбординг; демо-вход делает участником).

**Действия:**

| Действие | Кому | Что происходит |
|---|---|---|
| Войти в компанию | участник | контекст переключается; далее всё — внутри её данных |
| Создать компанию | любой пользователь | создаётся пустая компания, создатель — её админ (владелец) и единственный, кто её видит, пока никого не пригласил |
| Переименовать | админ | правка названия |
| Удалить | админ | с подтверждением; удаляются только данные этой компании |
| Пригласить участника | админ | по email; приглашённый получает доступ к просмотру и работе (объём — по роли) |
| Участники и роли | админ | выдать/снять роль (редактор/читатель), удалить участника (доступ исчезает целиком — включая просмотр); всё пишется в журнал («кто, когда, что выдал») |
| Журнал прав | админ | история изменения ролей и прав компании |
| Матрица прав | админ | включение/отключение отдельных прав для ролей (например, снять с редакторов право подтверждать отмену); админ-права неотчуждаемы |

Роль локальна по компании и не распространяется на другие компании.

## Стр. 0.1 «Загрузка данных»

Первый рабочий экран компании, пока её данные не загружены (позже — модалка с дашборда). Три пути — от простого к ручному:

| Путь | Как работает в UI |
|---|---|
| **А. Демо-импорт (главный)** | кнопка «Импортировать датасет». Без вопросов и подтверждений. Ответ: счётчики (задачи/люди/зависимости/история) |
| **Б. Свой файл** (xlsx/csv/json) | 1) файл → **превью сопоставления колонок** с сущностями сервиса с уровнями уверенности; 2) незнакомый формат → **вопросы пользователю** («что значит колонка "Сп"?»); 3) состояние обработки видно (загружено → сопоставление → вопросы → готово / ошибка), долгая AI-фаза не подвешивает страницу; 4) **импорт только после явного подтверждения** («Импортировать»); ответ: счётчики |
| **В. Ручной ввод** | формы-редакторы: команды, задачи, инженеры, зависимости — все поля кроме id опциональны, дозаполнение в любой момент |

**Правила, видимые пользователю:**
- повторный импорт не затирает вручную сделанные правки («ваши ручные правки сохранятся»);
- незнакомый формат без AI-ключа — деградация: шаблонное сопоставление + вопросы, без ошибки;
- импорт принадлежит текущей компании и не задевает соседние; [change 008]
- ошибки статусов понятны, зависший процесс заканчивается статусом «ошибка» с причиной, а не вечным ожиданием. [change 007]

## Стр. 1 «План квартала» — дашборд

**Что видит:**
- Шесть колонок-спринтов **с датами начала/конца каждого**. [change 010] В колонках — задача-карточки (сверху фильтр по командам).
- Статус каждой карточки — цветом **и не только цветом** (метка/иконка/текст): «запланирована», «перенесена» (с причиной), «кандидат на отмену» (оранжевая), «отменена» (с причиной), «выполнена» (серая, факт).
- Блок «Вне плана / не влезли в квартал» — отложенные/отменённые задачи **не исчезают**, причины видны.
- Виджет **Bus-рисков [есть в бэке]**: «N задач плана зависят от компетенций с единственным носителем» + список задач с ролями и их единственными носителями; роли без носителей тоже помечены. Клик — панель уязвимостей, переход на карту. [change 004, ручка готова]
- Пустое состояние, если плана нет: «Сгенерировать план» / подсказка «сначала импортируйте данные».
- Селектор **версий плана**: исходная → пересчитанные → …; актуальная помечена. [change 003 бэк готов]
- **Навигация уровнями** [change 006]: клик по колонке спринта → экран спринта (состав, даты, причины, привязанные риски) → клик по задаче → карточка; возврат на вид квартала. Задачи спринтов и «вне плана» сворачиваются в **группы по инициативам** с прогрессом («X из Y в плане»; завершённая инициатива помечена): инициативы — «макрозадачи» из задач (состав работ), спринты — не подзадачи, а окна времени (ось дат). [change 006]

**Действия:**

| Действие | Что происходит |
|---|---|
| Клик по задаче | карточка: название, инициатива, SP/часы, плановая разбивка часов по ролям (и **фактическая**, если есть данные) [change 011], зависимости, **причина текущего решения**, даты спринта/прогноз [change 010] |
| Сменить приоритет | drag-n-drop или число («меньше — раньше»); после несохранённых изменений UI подсказывает «пересчитать план» |
| Пересчитать план | создаётся **новая версия**; старые сохраняются; UI переключается на новую; календарь квартала не двигается [change 010] |
| Предложить отмену | оранжевый статус «кандидат на отмену» с причиной |
| Подтвердить отмену | второй шаг (право отмены): «отменена», причина фиксируется с именем подтвердившего; задача остаётся видимой |
| Выбрать версию | просмотр исторической версии; авторства правок видны [change 005] |

Конкурентные правки не затирают друг друга — правки разных людей образуют версии; выбор актуальной за лидом. [change 005]

## Стр. 2 «Спринт: факт и пересчёт» (раз в 2 недели)

**Что видит:** селектор спринта 1..6 с датами; текущая версия плана; какие спринты зафиксированы фактами.

**Действия:**

| Действие | Что происходит |
|---|---|
| Загрузить факт спринта N | отметить выполненные задачи (+ фактические SP; опционально — **фактические часы по ролям**). После отправки: **новая версия плана**, UI переключается; спринт N зафиксирован по факту, остальное пересчитано. Повторная отправка того же спринта заблокирована («409») |
| Пересчитать без факта | ещё одна версия плана (например, после смены приоритетов) |
| Смотреть риски | 4 типа предупреждений со списками затронутых задач: **выход за квартал** (с датами: «прогноз 2027-01-10 > конца квартала 2026-12-27») [change 010]; **сдвиг цепочки** зависимых задач (с новыми датами задач); **дефицит роли** на следующий спринт («нужно 160 ч, доступно 100 ч»); **изменение состава** плана (+/–). Плюс мягкое **грейд-предупреждение** (не блокирует задачу) [решение №8, change 010] |
| Смотреть сдвиги | «задача X: спринт 1 → 3»; что стало «вне квартала» |
| Читать «почему» | каждое объяснение связывает факт с следствием («из-за недобора SP в спринте 1 сдвинулось…») и может содержать **справочную категорию причины расхождения** из датасета [change 011] |

После пересчёта — возврат на дашборд для обработки кандидатов на отмену.

## Стр. 3 «Звёздная карта»

**Что видит:** людей **только текущей компании** в виде графа/карточек: команда = кластер, инженер = узел (роль, грейд, ставка). Полставочники в двух командах — в обеих с пометкой. Единственные носители компетенций — подсвечены.

**Действия:**

| Действие | Что происходит |
|---|---|
| Фильтры | команда, роль, грейд, навык, ставка |
| Клик по инженеру | анкета: все его компании (частичная занятость), часы/спринт по каждой, **предупреждения**: его навыки, где он единственный носитель |
| Клик по команде | состав, capacity SP/спринт (средняя velocity × 0.8), история прошлых спринтов |
| Открыть Bus Factor | компетенции/роли → число носителей, свод «вся компания / команда»; фактор ≤ 1 подсвечен; **текст методики и область расчёта видны рядом** (что считается и что навыки заявлены декларативно) |

Доступна сразу после импорта людей; план не нужен.

## Стр. 4 «Метрики квартала»

**Что видит:**
- **% выполнения квартального плана** — по **инициативам**: завершённые инициативы / включённые в исходный план × 100%; подпись **«факт»** или **«прогноз»** до конца квартала.
- **% по каждому из 6 спринтов** (бары): выполнено SP / было запланировано SP; факт по завершённым, прогноз по будущим (подписи текстом).
- База сравнения — **первоначальный план**: сколько инициатив вошло в исходный план, столько в знаменателе; пересчёты знаменатель не подменяют. Все цифры — в границах текущей компании. [change 008]

## Сводный маршрут по ролям

- **Консультант / внешний админ (мультикомпании)**: создаёт компании (единственный видящий их, пока не пригласил) → грузит датасет каждой → приглашает участников и раздаёт роли → отдаёт компании редакторам. [change 008/009]
- **Редактор (лид компании)**: данные → план → приоритеты → отмены → факт раз в 2 недели → риски → итоги квартала.
- **Читатель** (приглашён): только просмотр: план и причины, карта и Bus Factor, метрики. Не приглашён — компании для него нет.
